# Film Index 3.0 · 单应用版

一个仓库、一个 Docker 镜像、一个容器、一个 Python 服务进程、一套后台。

订阅与媒体整理已整合进 `film_index` 应用包，注册到同一个 Flask 应用，使用同一个持久登录会话。没有 Nginx 网关、内部 HTTP 代理、第二套后端或独立媒体服务端口。镜像从通用 Python 基础镜像构建，不再继承旧 NAS/媒体项目镜像，也不需要运行原来两个项目。

## 从原项目迁移

1. 停止原百度订阅、Film Index 或三容器 Hub 项目，保留所有文件。不要让新旧实例同时写同一配置目录。
2. 在新项目目录保存 `compose.yaml`，将 `.env.example` 另存为 `.env`。
3. 将 `PAN_CONFIG_DIR` 设为实际包含原 `config.json`、`.session-secret` 和 `history/` 的目录。将 `MEDIA_CONFIG_DIR` 设为原来包含 `config.yaml`、`user.db`、媒体数据库及缓存的目录。`PAN_LOG_DIR` 沿用原日志目录。
4. `MEDIA_ROOT` 沿用原来映射到 `/media` 的宿主机媒体父目录。若以前使用其他容器路径（例如 `/tv`），在 YAML 中额外保留相同路径映射，避免原目录同步规则失效。
5. 创建一个 Compose 项目并启动唯一的 `film-index` 服务，访问 `http://NAS的IP:18520`。
6. 用原百度订阅后台账号密码登录，原有新增后台账号继续有效。媒体模块不再提供第二套账号管理。

```sh
docker compose pull
docker compose up -d
```

原账号、网盘 Cookie、任务 UID、转存记忆直接读取原配置文件，不按目标目录是否存在判断重复。媒体库、目录同步、整理历史、识别词和 TMDB 配置继续读取原媒体配置与数据库。升级前自动备份关键配置和 SQLite 数据库到 `./data/backups`；备份不会清空原数据。媒体软件内保存的旧登录字段保留为兼容数据，不再参与登录。

如果原本有账号任务却看到首次生成密码和空任务，说明配置目录挂载错误。停止新项目并修正路径，不要覆盖原配置。

## 全新安装

使用默认路径即可。首次后台管理员密码显示在容器日志中。后台登录与百度网盘 Cookie 是两回事；过期的网盘 Cookie 仍需更新。

## 运行与界面

保持白色半透明玻璃、纯文字左对齐导航。常用前端页面空闲预热，目录按需异步读取。一个 Waitress 服务器监听 5000，默认 8 请求线程；目录整理和订阅调度在同一进程内运行，不启动 PM2、虚拟显示或浏览器服务。默认 512MiB 是内存上限，实际用量以 NAS 监控为准。

`ffmpeg`、`rclone` 与固定校验版本的 MinIO 客户端包含在镜像中；Rclone 和 MinIO 需挂载原凭据目录。字幕检索所需浏览器仅在执行该功能时启动，并在检索后关闭，不作为独立后台服务运行。PT 下载、做种、站点及索引器功能不启用。

## 构建与源码

```sh
python3 scripts/source_bundle.py
docker build -t film-index:local .
```

整个项目源码在此仓库；网络源码下载入口为 `/project-source.zip`，不包含实际挂载数据、账号密码或 `.env`。沿用原项目许可，按 AGPL-3.0 分发。历史来源与改动记录见 `UPSTREAM.json`。

发布检查包括原账号与新增账号登录、任务和转存记忆保留、媒体数据库持久化、退出和密码变更撤销权限、一个容器/进程/Flask 应用，以及全部保留媒体页面。实际百度网盘和 NAS 媒体文件操作需要部署后使用自己的配置验证。
